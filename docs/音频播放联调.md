# Tab5 音频播放联调（第一阶段）

> 历史阶段记录。v1.0.0 已保留暂停恢复和分包加密回归，输出改为双路混音、设置页音量；开机自检已删除。当前功能、实机结果和限制以 [v1.0.0 发布说明](releases/v1.0.0.md) 与[执行记录](执行记录.md)为准。

目标：让 iPhone 的单路音乐 PCM 经现有 CarPlay/AirPlay 链路在 Tab5 输出。
目前只有离线测试和编译证据，不能据此认定手机已向 Tab5 发送音乐或扬声器已出声。
本轮已知待测组合：Tab5 + iPhone X，iOS 16.7.16；板卡芯片 revision 尚待读取。

## 本轮变更

- 播放连续空缓冲约 100 ms 后解除旧 RTP 时间戳锚点，恢复收包时重新预缓冲。
  这覆盖暂停后发送端时间戳没有随本地静音播放继续前进的情况，避免永久拒绝迟到包。
  短时丢包仍按原时间轴补静音；连接代数校验、单/双声道和端序转换保留。
- 将已有 RTP 固定头/ChaCha20-Poly1305 解密提取为可测试模块，解密失败不暴露 PCM。
  协议布局及密钥派生保持原实现；合成测试不能证明 iOS 实际协议兼容性。
- 输出打开时显式设置本地音量及取消静音，记录 codec 打开、首批真实 PCM 写入和周期状态。
- 将可选开机音频自检安排在 USB 初始化之前完成，避免与播放任务同时操作 codec/I2S。

## 构建和离线检查

```sh
./scripts/check_cli.sh
./scripts/test_host.sh
source <esp-idf-v5.5.3>/export.sh
./scripts/test_crypto.sh
python3 scripts/fetch_openh264.py
./scripts/build.sh
./scripts/test_decoder.sh
```

`test_host.sh` 覆盖 44.1/48 kHz 的短时丢包、持续欠载、暂停时间戳恢复、重新预缓冲
及旧连接拒绝。`test_crypto.sh` 新增合成加密 RTP→解密→PCM 缓冲→逐字节输出回归，
覆盖单/双声道、端序、认证数据/密文/tag/nonce 篡改、错误密钥、截断和非法格式。

## 真机步骤

1. 按《实机验收》的烧录前流程确认 silicon revision、分区和备份。不得假定默认
   v1.x 构建能烧到任意 Tab5。保留 NVS、认证身份和分区表。
2. 先不接手机，通过 `idf.py menuconfig` 开启 `TAB5_AUDIO_TEST`；它在 USB 初始化前
   播放短音、采样麦克风峰值。人耳确认出声，记录 `Tone write complete` 和 `MIC` 日志。
   codec 返回成功、麦克风峰值变化均不等于 CarPlay 音频或麦克风上行验收通过。
3. `TAB5_AUDIO_VOLUME` 控制播放流打开时的本地输出音量，默认 30%，0 为静音。
   本轮没有实现手机音量命令。正常联调可关闭 `TAB5_AUDIO_TEST`。
4. 连接 iPhone X / iOS 16.7.16，保持已验证的认证/USB 配置，播放普通音乐。
   保存从连接前到播放、暂停、恢复、拔线后的完整串口日志；不保存语音或密钥。
5. 按下表定位最早缺失或出错的阶段。出现格式拒绝时记录格式值，不能通过虚报
   未实现的音频能力来绕过错误。
6. 暂停后恢复、切歌和重新插拔；确认输出恢复且不播放上次连接的音频。
   连续播放 30 分钟，记录是否有卡顿、爆音、音画漂移和队列/错误计数。

| 日志 | 能证明什么 / 排查方向 |
|---|---|
| 没有 `SETUP requested` | 尚未看到受支持的音频 SETUP；检查会话建立、能力协商及手机输出路由 |
| `SETUP rejected` | 字段/格式不支持、输出被占用，或 codec 打开失败；按具体原因排查 |
| `OUTPUT_OPEN` | codec 打开、音量和取消静音调用成功；不证明收到音频 |
| `ready ... data=... control=...` | 音频端口已建立；不证明手机向这些端口发送音频 |
| `PCM_FIRST` | 首个认证 PCM 已被播放缓冲接受 |
| `auth_errors` / `format_errors` | 分别为认证解密失败、包结构或采样对齐不符 |
| `sink_drops` | 解密成功但播放层拒绝；结合队列和 rejected_packets 判断 |
| `OUTPUT_FIRST_PCM` | 首批真实 PCM 写入 codec 返回成功；仍需人耳确认 |
| `OUTPUT_STATUS` | 已写真实帧、排队帧、欠载、拒绝包、重新缓冲次数；每约 3 秒输出 |
| `OUTPUT_WRITE failed` | codec/I2S 写入失败，当前输出已停止，需要重新建立流 |

## 尚未完成

- 真机出声、暂停恢复和长期稳定性验收。
- 多流混音、导航压低音乐、手机音量控制、采样时钟漂移补偿。
- 麦克风上行、Siri/通话双向音频及 AEC。

这些能力继续保持未验证/未实现状态，不扩大 `/info` 的输入或音频格式声明。
