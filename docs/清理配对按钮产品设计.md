# 等待连接页：清理配对按钮

日期：2026-11-14。状态：已实现、烧录并完成用户实机确认（2026-11-14）；下文保留设计要求，实际结果见末节。

## 目标与范围

用户直接在 Tab5 上清除旧手机的本机信任记录，释放配对空间，再连接另一部 iPhone；无需电脑或临时维护固件。

本功能解决手动换机，不承诺扩大配对容量，也不提供多手机列表、自动删除旧记录或恢复出厂设置。依据现有 `main/app_ui.c`、`main/app_main.c` 及《iPhone12配对存储失败分析-2026-11-13.md》设计。

## 等待页布局

延续现有品牌、居中连接提示和底部模式信息。以 1280 × 720 横屏为基准：

- 顶部：Tab5 / CarPlay，保持现有薄荷绿。
- 中部标题：连接你的 iPhone。
- 说明：将已解锁的 iPhone 连接到 USB-A 接口。
- 底部左侧：Device mode；底部右侧：描边次要按钮「清理配对」。边距 48 px，按钮建议 224 × 64 px，圆角 8 px，文字 24 px。
- 日常等待页不使用醒目的红色按钮；仅最终确认使用危险操作样式。
- 保持当前深色背景 #101820、正文 #e8eef3、辅助文字 #aab8c5、强调色 #70c6ad。错误沿用 #ffb6a3。

预览使用中文表达产品文案。当前固件为英文界面，首版实施可统一采用下文英文映射并复用现有字体；若采用中文，需补充对应字形并检查固件体积及实机显示，避免中英混排。

## 操作流程

1. 用户点击「清理配对」，打开确认窗口，不立即删除。
2. 若 USB-A 仍接着手机，窗口提示「请先拔下 USB-A 接口上的手机」，确认按钮禁用；拔下后自动变为可确认。无需再次打开窗口。
3. 确认窗口标题：「清除手机配对？」。正文：「将清除 Tab5 保存的全部手机信任记录。再次连接时，需要在 iPhone 上重新确认信任。音量、亮度等设置保留。」按钮左侧「取消」、右侧「清除配对」。取消默认获得焦点。
4. 点击确认后显示「正在清理配对…」，禁止重复提交，不显示虚构进度百分比。期间不要连接手机。
5. 只有清除、提交并校验成功，才显示「配对已清除」，说明「连接要使用的 iPhone，解锁后确认『信任』。」直接进入可连接状态，无需额外点击“完成”。下一次连接事件替换成功提示。
6. 如果没有配对记录，显示「没有需要清理的配对」，仍可直接连接手机。

目标体验为无需重启即可返回等待连接。若实现时不能可靠清空内存中的旧身份，改为清除成功后自动重启，并同步把进度/成功文案改为「配对已清除，正在重启…」；不能一边保留旧身份一边提示清理成功。

## 入口与状态规则

| 状态 | 入口与行为 |
| --- | --- |
| 未连接、等待连接 | 显示，可点击；不自动弹出清理窗口 |
| 等待手机信任 | 显示，可打开窗口；必须拔下手机后才能确认 |
| 连接、认证、网络/媒体启动中 | 入口置灰，提示「连接中，请先拔下手机再清理」 |
| 配对存储失败 | 显示同位置按钮；主文案改为「无法保存手机配对」，说明「可清理旧配对后重新连接」。不要把所有存储异常都说成容量已满 |
| 其他失败、重试等待 | 显示入口；仍须拔下手机且完成会话退出后才能确认 |
| 正在退出会话 | 确认保持禁用，提示「正在结束连接…」；不能因已经拔线就提前放行 |
| CarPlay 正在显示 | 隐藏入口，不覆盖导航、音乐或触摸区域 |
| 正在清理 | 阻止再次确认，暂缓新手机配对；触摸不能传给旧 CarPlay 会话 |

用户停留确认窗口时，若检测到重新插入手机，立即禁用确认。若会话已经进入 CarPlay，关闭尚未执行的确认窗口，不进行删除。

## 异常反馈

- 清理失败：「配对未能清除，请重试。」提供「返回」「重试」。不能承诺失败时记录一定完整，也不能显示成功。重试仍须满足断开条件。
- 会话退出失败或超时：提示「连接尚未结束，请重启 Tab5 后重试」，不开始删除。
- 清理超过 5 秒：显示「清理耗时较长，请稍候」；这是提示阈值，不是允许发起第二个清理任务的超时。失败或卡死必须由工作任务超时/既有监护收敛，不能在 UI 线程无限阻塞。
- 清理中断电：下次启动检查实际存储状态，正常进入等待或明确报错；不要保存一个会在每次开机反复清除的维护开关。
- 新手机插入过早：清理执行前重新检查连接状态，已连接则拒绝删除；清理执行期间串行处理存储，完成后才处理新的 USB 连接，不与配对写入并发。
- 手机未出现信任提示：先提示保持解锁并重新插入；不默认要求用户重置手机全部设置。

## 数据边界与实现约束

- 仅删除 `tab5_pair` 命名空间中的记录；不可调用整分区擦除。
- 保留 `tab5_ui` 音量/亮度、`tab5_ap_id` 接收端身份、`tab5_ap_pair` 记录和 SD 日志。产品文案使用“手机信任记录”，不暗示清空所有协议身份。
- UI 仅提交请求；后台任务在 USB 已断开、会话已退出且配对写入已停止后执行。清理入口与自动连接/配对写入互斥；UI 持续响应。
- 提交成功后重新读取验证目标命名空间为空，再清理内存缓存并报告成功。无记录为幂等成功。
- 日志记录请求、取消、拒绝原因、开始、清理结果及耗时；不输出证书、私钥、手机唯一标识。
- 不复用当前“烧录维护固件后永久等待”的交互路径；正式固件内提供一次性操作。

## 验收标准

1. 未连接时，从等待页最多两次点击完成清理；取消、点遮罩或返回均不删除记录。
2. 手机仍连接、会话未退出时，无法执行删除；拔线后无需重新打开窗口。
3. 清理只作用于指定命名空间；音量、亮度及其它身份保持不变，日志可读。
4. 连点确认、清理中插入手机、不存在记录、写入失败均有确定结果，无死锁或假成功。
5. 清理后新 iPhone 确认信任，完成 CarPlay 视频和音乐验证；换回旧手机能够重新配对。
6. CarPlay 中无按钮覆盖，触摸、导航播报和音乐不受影响。
7. 断电或异常退出后可恢复；不会每次开机自动清除。

## 实施结果（2026-11-14）

- 正式界面使用英文，沿用现有 Montserrat 字体和深色布局。等待页右下角为 `Clear pairing`；确认窗口提供 `Cancel` 和 `Clear pairing`。只有连接/配对线程完全退出并空闲 1 秒后才能确认执行。
- `main/pairing_reset.c` 接收非阻塞请求，USB 所有者任务在事件处理及清理后再次校验，执行限定命名空间的 erase/commit/空记录校验。沿用独立 USB 15 秒进度监护，清理不重启设备。
- 失败时回到结果页，通过同一入口重新确认重试；无记录时显示 `No saved phone pairing`。新连接状态优先于过期清理结果。
- 主机 ASan/UBSan 回归及实际 LVGL 界面测试通过。LVGL 测试覆盖取消、未拔线/退出中禁用、连续相同结果、耗时提示、失败、空记录和 Streaming 隐藏；生成图像已检查。
- 固件 `19f34ead` 已仅写入 factory 应用区并通过哈希校验。实机 Cancel 未触发删除；确认后 `tab5_pair` 清理及校验成功，耗时 7 ms。用户确认「清理正常，已进入 CarPlay」；串口确认重新保存配对、TLS、iAP2 和 Streaming 成功。
- 这是换机功能及短时视频/音频验证；断电中断、真实闪存错误及清理期间恰好插拔的实机故障注入未执行。存储失败/并发拒绝分支由主机测试验证，不等同于全部硬件故障验收。

记录与证据见 `docs/执行记录.md`、`artifacts/device-2026-11-14/pairing-button/`。

补充复验：同一正式固件完成单次连续采集。取消后重新确认清理用时 4 ms，配对记录为 0 后重新配对成功；连续投屏约 4 分钟，视频 2,824 帧无错误、音乐 31,017 包无 bad/采样丢包或乱序。用户按要求手动拔线后，确认等待页和 Clear pairing 按钮恢复。该闭环已通过，记录详见执行记录的“用户要求重新完整验证”。
