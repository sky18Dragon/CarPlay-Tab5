# CarPlay-Tab5 技术实现方案

原始方案日期：2026-11-05。以下保留最初阶段设计与当时核查结果，不作为当前实现状态。

2026-11-06 更新：按用户要求，改为先完成前四项离线开发，暂缓实机调试。当前代码、接口、测试和待适配限制以 [四项开发交付](四项开发交付.md) 为准。USB Host 已由应用安装过滤器/daemon，BSP 负责供电；完整协议和媒体组件已接入，文中“待移植”“未检测到串口”等是历史状态。麦克风/AEC 不在本次四项内。

## 1. 输入与技术决策

输入为用户提供的《CarPlay-Tab5 实践方案》。该文档是需求与设计参考，其中的历史可行性判断、示例和操作步骤不作为已经验证的事实。

采用原生 ESP-IDF C/C++ 工程。先完成 M0/M1 板级基线，待硬件及认证路径验证通过再移植完整协议。不把 S3 固件直接刷入 P4，不复制上游 Release 中的认证身份。

固定 ESP-IDF v5.5.3、espressif/m5stack_tab5 1.3.2、LVGL 9.3.0、esp_lvgl_port 2.6.2；其余依赖以 dependencies.lock 固定。选用本机已安装且可执行的稳定 SDK，避免引入尚未验证的主线 SDK；BSP 组件声明兼容 IDF >=5.4。编译发现自动选中的 esp_lvgl_port 2.9.0 使用本 SDK 不具备的 DSI 回调，故显式固定 2.6.2。USB 使用 BSP 提供的一体化启动接口，不另起第二个 Host daemon。实际编译结果见执行记录。

用户确认屏幕为 **ST7121**。M5Stack 官网版本历史说明 2026-04-28 从 ST7123 切换到 ST7121。实际下载的 BSP 1.3.2 已含 ST7121 初始化表：探测触摸地址 0x55，读取寄存器 0x0000，FW=1 识别 ST7121、FW=3 识别 ST7123。采用 BSP 自动识别，未知版本不强行套用。其 LCD 复位低电平采用输出，高电平切回输入上拉，符合 M5Stack 对 I2C 稳定性的要求。

## 2. 核查结果与边界

- Tab5 官方配置：ESP32-P4、32 MB PSRAM、16 MB Flash、MIPI-DSI 屏、ES8388 输出与 ES7210 输入。复用 BSP 的 I2C、扩展器、显示及音频驱动。
- USB-A 供电开关由 BSP 的 IO 扩展器管理；不将 BSP_USB_EN 当作主控 GPIO，也不承诺 API 的 limit_500mA 参数真的限流（该板文档标记未使用）。直接调用 bsp_usb_host_start，由 BSP 选择其适配的 USB 控制器。不要照搬 S3 GPIO19/20 的 PHY 设置；BSP 宏本身也须结合 P4 原理图判断，不额外烧 eFuse。USB 组件的默认 peripheral_map=0 在 P4 选择高速控制器，具体连接速度以枚举日志实测。
- P4 H.264 是编码硬件，解码仍需软件。采用上游固定的 OpenH264 2.6.0 portable C/C++ 解码路线，禁止误用 H.264 encoder API。High Profile/参考帧需求必须与真实流核对。
- 上游公开源码缺少完整认证身份；能编译不表示 iPhone 接受认证。上游音频仅为 PCM 接收诊断，尚无 I2S 出声、麦克风上行的通过证据。
- 本次没有检测到 Tab5 USB 串口，无法取得枚举、显示、声音或性能实机结论。

P4 v0/v1 与 v3 系列存在 SDK 明示的硬件不兼容。默认构建配置选择 v1.0–1.99、360 MHz；另外验证 v3.1–3.99 的编译。最终选择必须以设备芯片信息为准，ST7121 屏幕型号并不能推断 silicon revision。

## 3. 架构与数据流

```
USB Host (BSP/IDF)
  -> descriptor probe [当前实现]
  -> USBMUX -> Lockdown/TLS -> CarKit/iAP2/auth [待移植]
  -> NCM/NTB16 -> esp_netif/lwIP IPv6
  -> AirPlay RTSP + Event + Timing + Screen + Audio
      -> bounded H264 queue -> OpenH264 -> RGB565 -> MIPI DSI
      -> authenticated RTP PCM -> jitter buffer -> ES8388
Touch BSP -> orientation/letterbox mapping -> HID -> Event channel
ES7210 -> capture/AEC -> microphone uplink [第二阶段]
```

USB 客户端回调只记录事件；在客户端任务上下文开关设备并解析缓存描述符。先不 claim 接口、不发 Apple 模式切换命令、不请求手机信任。解析接口号、alternate setting、class/subclass/protocol、端点地址/类型/包大小，区分 Apple VID 与真实 iPhone 身份（VID 不能单独证明机型）。断开释放句柄；记录连接/断开计数与最小空闲堆。

后续协议状态：DETACHED -> ENUMERATED -> USBMUX -> TRUST_PENDING -> LOCKDOWN -> IAP2_AUTH -> NCM_READY -> SESSION -> STREAMING。每次连接分配 generation；异步完成带 generation，过期完成不得更新新会话。断开先停止生产者，再取消传输、等待回调回收、释放接口，最后关闭设备。各阶段设置超时，重试指数退避且有上限，不循环擦除配对 NVS。

认证接口分别表达 MISSING、READY、REJECTED、ACCEPTED；仅存在文件不能置 ACCEPTED。认证材料不进仓库/日志；Lockdown 配对身份与 CarPlay 认证身份分开保存。

## 5. 媒体设计与预算

手机的逻辑排版尺寸由像素数和声明的物理长宽比共同决定：逻辑宽度取像素宽度与“像素高度×物理长宽比”中的较大者，图标约 60 逻辑点。因此可以声明 16:9，同时只让手机编码 1024×192，界面仍按 1024×576 排版，再由 PPA 拉伸。默认 1024×192/16 FPS，可选 1024×240/12、1024×360/7、1024×576/5、852×480/5、640×384/5、480×288/6、320×192/8；这些是试验档位，不是性能承诺。CarPlay 主页固定 4×2 网格，逻辑宽度低于 640 时图标重叠，不存在 6 或 4 图标布局。默认单主屏，暂不同时解两路。

1280×720 RGB565 一帧 1,843,200 字节，双缓冲 3,686,400 字节；480×288 I420 一帧 207,360 字节。OpenH264 内部参考帧、码流与任务栈另计；32 MB PSRAM 不是全部可用于帧缓冲。USB DMA 使用驱动分配接口，禁止随意将普通 PSRAM 指针交给 DMA。

码流队列按字节数与帧数双重限流（起始预算 512 KiB/3 access units，后续压测调整），拥塞时丢弃完整 access unit 并请求 IDR，不能任意裁剪 H.264 字节。显示缓冲在刷新完成前不复用。触摸横屏变换后扣除 letterbox 偏移，再映射至协商像素范围，黑边按下忽略，活动拖动出界钳位并确保释放事件送达。

音频按实际协商格式创建 codec，先支持 16-bit LPCM，明确采样率/声道/端序；例如 48 kHz 双声道每秒 192,000 字节，60 ms 缓冲 11,520 字节。丢包补静音，独立高优先级任务写 I2S，网络回调不阻塞等待播放。麦克风基线只统计峰值、不持久化语音；AEC 和上行会话后续独立验收。

## 6. 执行与阶段门槛

| 里程碑 | 本次/后续交付 | 通过标准 |
|---|---|---|
| M0 | 可编译 BSP 固件，显示/触摸、可选音频自检 | 真机正常显示，触摸四角正确，短音/麦克风峰值有效 |
| M1 | USB 描述符探针 | iPhone 20 次插拔恢复、无持续堆下降 |
| M2 | USBMUX/Lockdown/iAP2，认证 provider | 合法身份路径明确，真实认证成功日志 |
| M3 | NCM/IPv6/RTSP | 收到真实媒体并正确校验 |
| M4 | OpenH264 + 显示 | 各档平均/最慢帧、30 分钟无崩溃 |
| M5 | HID 与 PCM 播放 | 点击拖动、音乐/导航 30 分钟正常 |
| M6 | 麦克风/AEC/稳定性 | Siri、通话、2 小时及电源异常回归 |
