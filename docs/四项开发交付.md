# 前四项离线开发交付

更新：2026-11-06。范围为用户要求先开发、后集中实机调试的四项。代码已接入应用；编译和主机测试证据不等于手机认证、实际播放或性能验收。实机工作保持暂停。

## 1. 会话管理与模拟

`main/core/session.c` 定义 USB 枚举、信任、Lockdown、认证、网络、媒体、停止和失败状态；`app_session.c` 由 USB 所有者任务推进，工作线程只投递带连接代次的事件。过期事件忽略，缺少认证材料或认证拒绝停止重试；通信超时执行 1/2/4 秒退避，最多三次。取消后等待 USB 回调和协议任务退出再释放资源。

`usb_probe.c`、`mux_channels.cpp`、`lockdown_client.cpp`、`iap2_client.cpp` 已接入真实事件。认证客户端通过 auth_port 获取证书和签名，核对签名 ACK、手机接受和识别结果，等待 NCM IPv6 后启动本地媒体服务。默认没有真实 provider；NCM 接口配置为 -1 时不会假定上游手机配置正确。

测试分别覆盖状态核心、实际 app_session 适配层、实际 iAP2 客户端模拟成功及五类失败；模拟的 provider/NCM/服务不能证明真实手机端到端认证。

## 2. NCM 与 RTSP

`ncm_host.cpp` 使用 CDC Union 描述符关联控制和数据接口，支持 64/512 字节 bulk 端点、NTB16 分片重组和有界发送队列，连接 esp-netif/lwIP IPv6。断线等待 outstanding DMA 回调，不提前释放传输缓冲。

AirPlay RTSP、pairing、control、timing、screen 和 audio 组件已编译链接。`airplay_service.c` 负责身份、熵源和服务生命周期；停止服务后再关闭媒体。RTSP 解析有长度限制，拒绝不合法头、溢出正文和错误后的继续解析。加密控制与屏幕数据使用 Mbed TLS 完整性校验。

现有手机观测配置仍为 USBMUX 配置 3。NCM 配置切换、设备特定控制请求和实际吞吐需实机适配；当前驱动并非任意 NCM 设备的通用兼容实现。主机测试覆盖描述符、NTB16、RTSP、plist、加密控制分片到 RTSP 解析、屏幕 HKDF/截断/篡改/重放。

## 3. 视频与触摸

`media_routes.cpp` 将认证后的 H.264 配置/AU 接到 `video_output.cpp`。队列同时限制 3 个 AU 与 512 KiB；丢失参考链后重置解码器并通过 event 通道请求 IDR。连接代次隔离旧帧和旧丢帧标记。

固定 OpenH264 v2.6.0 portable 解码器，I420 打包后由 PPA 完成色彩转换、缩放和旋转，写入面板帧缓冲（不经 LVGL）；解码和显示并行运行。默认请求 1024×192、16 FPS；解析和重建分别运行在两个核上（`CONFIG_TAB5_VIDEO_PROFILE_HEIGHT`），手机按 16:9 排版后纵向压缩，PPA 拉伸回全屏，高于 320×192 的档位为试验配置，试用跑不动或未判定时回退到 320×192。输出尺寸最大检查为 1280×720，不代表解码性能或恶意 SPS 的内部内存预算已经实测。

触摸扣除黑边，黑边首次按下忽略，拖动越界钳位，抬起和取消发释放。`hid_output.cpp` 独立队列投递单指 12 字节报告，发送时在控制通道锁下验证 epoch，避免旧会话点击送入新会话。

真实解码主机回归覆盖 High Profile 合成首帧及 32 帧 LTR 的逐帧像素 CRC，组合链路为 screen codec→AU 队列→解码→触摸/HID。没有用假彩色图替代解码验证。USB 关闭的离线演示以 4 FPS 循环播放合成素材，并输出本地触摸，界面明确标注 Simulation。

## 4. 音频接口与界面

认证后的 RTP PCM 写入 timestamp jitter buffer，支持 44.1/48 kHz、16-bit、单/双声道，转换网络端序；处理乱序、重复、回绕和欠载静音。60 ms 预缓冲，最大 4800 sample frames。独立任务以 10 ms 块写 codec，网络线程不等待音频播放。

当前输出支持一路 PCM，同时第二路 SETUP 返回失败；没有多流混音、时钟漂移补偿、麦克风上行或 AEC。ES8388 实际听感、音画同步和长期稳定性待实测。

`app_ui.c` 提供实际 LVGL 状态页、错误原因、模拟标识和视频画布；不是静态设计图。主机 framebuffer 渲染覆盖断开、缺认证、模拟播放和清屏。界面使用英文，未引入中文字库。

## 复现与验收证据

从根目录运行，先 source ESP-IDF v5.5.3/export.sh：

| 检查 | 命令 | 证据边界 |
|---|---|---|
| 默认 P4 固件 | `./scripts/build.sh` | 编译链接，不烧录 |
| 主机核心及适配回归 | `./scripts/test_host.sh` | ASan/UBSan，虚拟时钟/传输桩 |
| 实际 H.264 解码 | `./scripts/test_decoder.sh` | 固定合成码流、逐帧 CRC |
| 实际密码库与协议组合 | `./scripts/test_crypto.sh` | Mbed TLS + 生产 cipher/screen/RTSP；无手机 socket 会话 |
| 实际 UI 渲染 | `cmake -S tests/ui -B artifacts/ui-build && cmake --build artifacts/ui-build && ./artifacts/ui-build/render` | LVGL 主机 framebuffer，无 DSI 硬件 |

独立离线配置使用 artifacts/sdkconfig.offline，CONFIG_TAB5_OFFLINE_DEMO=y：

```sh
idf.py -B artifacts/offline-build -DSDKCONFIG="$PWD/artifacts/sdkconfig.offline" build
```

默认产物 build/carplay_tab5.bin；演示产物 artifacts/offline-build/carplay_tab5.bin。本机配置、测试产物及证据放在 artifacts，未纳入源码。正式版本仍应重新构建，不能把这些产物当成已适配所有 Tab5/iPhone 的发行固件。

## 恢复实机时的待办

1. 保持既有配对数据，确认目标 iPhone 描述符、NCM 配置和接口号。
2. 接入可用的认证 provider，核对真实 iAP2/识别/StartSession/RTSP 全链路。
3. 验证板上 High Profile 解码、触摸 HID、单路声音和媒体断开顺序。
4. 测量各档 FPS、延时、CPU/PSRAM、20 次插拔与至少 30 分钟播放；按结果调整档位和缓冲。

上述实机待办没有在本轮执行。现有 Lockdown 配对成功不能替代 CarPlay 认证成功。

最终结果：上述默认/演示固件构建、主机回归、实际解码、加密协议组合与 UI 渲染均通过。固件大小及 SHA-256 见 artifacts/offline-delivery/firmware.json；构建与回归日志保存在同目录。
