# 离线开发与集中联调计划

更新：2026-11-06。依据用户调整，先推进不依赖设备的开发，再集中调试和适配。实机暂停期间不烧录、不启动串口监听、不主动发起手机配对。

## 当前基线

已有 USB 配置扫描、USBMUX、Lockdown 配对/TLS、CarKit/iAP2 诊断代码及主机测试。第一部手机的配对与 TLS 已实测；换机隔离逻辑已加入，第二部 iPhone 12 Pro Max / iOS 16.1.1 的配对尚未完成。CarPlay 接收、音视频和交互尚未贯通。

## 开发顺序

1. 会话管理：统一连接代次、阶段、错误、超时和退出逻辑；使用虚拟时钟与模拟传输验证断开、重连、迟到回调。区分配对、CarPlay 认证与媒体可用状态。
2. 传输与协议：独立 NTB16 边界解析、RTSP 增量解析、有限长度消息队列；构造正常、截断、超长、循环引用与多包输入。随后接入设备传输适配层。
3. 视频路径：完整 access unit 队列、背压和 IDR 请求接口，解码器封装、颜色转换与帧所有权；用合法本地测试码流验证，不宣称已收到 iPhone 视频。
4. 交互与音频：letterbox 坐标映射、按下/拖动/释放状态；PCM 环形缓冲、乱序/欠载策略及格式检查。屏幕、触摸、codec 调用集中在板级适配层。
5. 应用界面：显示连接阶段、信任等待、认证缺失、错误和重试状态；提供明确标注的模拟模式，模拟成功不得改变真实认证状态。
6. 集成：固件编译、主机测试、内存预算与模拟端到端回归，形成待实机验证清单，再恢复集中联调。

每步交付对应实现、自动化验证及尚未验证项，避免把接口占位当作功能完成。

## 集中实机验证

恢复实机后依次进行：第二部手机独立配对及旧身份复用 → CarKit/iAP2 认证与协商 → NCM/IPv6 → 真正媒体接收 → 解码/显示性能 → 音频与触摸 → 插拔与长时间运行。

认证 provider 可以先定义接口及模拟实现；真实认证仍需有效材料和手机响应。USB 时序、iOS 差异、板上解码帧率、DMA 与音频时钟不能由主机测试代替。已有板级验证保留，后续仍可能根据真实协商结果调整实现。
