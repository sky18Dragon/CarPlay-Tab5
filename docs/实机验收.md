# 实机验收

## 烧录前

1. USB-C 将 Tab5 接到开发主机；先只连接 Tab5，不连接 iPhone。记录板卡背面 ST7121 标识。
2. 读取芯片 revision、Flash 大小、现有分区。当前默认构建支持 P4 v1.x；另有 v3.1–3.99 构建验证，但硬件 revision 尚未知。不要使用强制刷写参数。
3. 保存现有完整 Flash 备份及 SHA-256；备份可能包含凭据，留在本机。确认本固件的 factory 分区布局与恢复方法后再烧录。
4. 本工程没有自动烧录脚本，当前没有执行烧录、整片擦除、eFuse 写入、C6 更新或 SD 操作。

## M0 显示/触摸

- 串口出现 `BRINGUP` 和固件 IDF 版本。
- BSP 应报告 `Discovered board version 3 (LCD ST7121, Touch ST712x, FW 1)`。这条“board version 3”是 BSP 屏幕版本，**不是 ESP32-P4 silicon revision 3**。
- 观察 RGB 色块、横屏文字、40% 背光。屏幕花屏/黑屏或探测不符时记录完整上电日志。
- 触摸四角和中心，核对坐标方向、范围；按下/释放各一条日志。当前没有 CarPlay HID 回传。
- 若显示初始化阻止后续调试，在 menuconfig 关闭显示诊断，单独验证 USB。

## M0 音频（可选构建）

- 开启 TAB5_AUDIO_TEST，启动播放短音；`Tone write complete` 只证明写入接口返回，必须由人确认真正出声。
- MIC 日志应 read=OK，轻声说话时峰值随之变化。峰值不能证明双麦克风各自正常，更不证明 AEC/Siri。
- 音频错误须记录 codec/I2S 日志，长稳与 DMA 故障尚未覆盖。

## M1 USB

1. Tab5 独立稳定供电，iPhone 用支持数据的 USB-A 线接 Tab5 Host，首轮不加 Hub。
2. 观察 `CONNECTED`、VID/PID、速度枚举值、IF/EP 描述符。Apple VID 05ac 仅为厂商识别，不能据此声称 CarPlay 已连接。
3. 拔出出现 `DISCONNECTED`，再次插入能重新枚举。连续 20 次，记录线材、iPhone/iOS、每轮计数与堆占用。
4. 比较稳定基线下空闲内部堆、PSRAM；最小空闲堆是历史低水位，不会恢复，不能把它当作泄漏的唯一证据。
5. 枚举失败检查 IDF USB 日志、线材和 VBUS 电流；软件参数不保证限流或足够的手机充电功率。
6. 30 分钟通电与反复插拔无 panic、看门狗、持续内存下降。该程序不发 Apple 特定控制请求，手机没有信任提示是预期行为。
