# Tab5 软件认证接入

更新：2026-11-14。当前仓库已附带实验性 iAP2 软件认证材料，克隆后可直接选择带认证构建。该身份是公开共享的实验身份，不代表 Apple/MFi 认证，不保证全部手机或 iOS 版本持续可用。

## 获取仓库内材料

直接查看[认证材料目录](../secrets/mfi/README.md)，无需另行下载或提取 APK：

| 文件 | 用途 | 大小 |
|---|---|---|
| [identity.pk8](../secrets/mfi/identity.pk8) | PKCS#8 P-256 私钥 | 67 字节 |
| [certificate.p7b](../secrets/mfi/certificate.p7b) | PKCS#7 证书容器 | 607 字节 |
| [certificate.der](../secrets/mfi/certificate.der) | 用于自检的 DER 证书 | 558 字节 |

推荐克隆或更新当前 `main`，文件会位于现有构建要求的 `secrets/mfi/`。也可通过上面的文件页面下载原始文件，保持文件名和目录层级；不能保存 GitHub 的 HTML 页面代替二进制文件。

在仓库根目录校验：

```sh
(cd secrets/mfi && shasum -a 256 -c SHA256SUMS)
```

三项均应显示 `OK`。[校验清单](../secrets/mfi/SHA256SUMS) 用于核对下载是否完整，不代表对更早来源或授权的证明。

## 构建与烧录

使用 ESP-IDF v5.5.3，在仓库根目录运行：

```sh
source <esp-idf-v5.5.3>/export.sh
python3 scripts/fetch_openh264.py
./scripts/build.sh --software-auth
```

该命令显式设置 `TAB5_SOFTWARE_AUTH=ON`，CMake 将上述三份文件嵌入 `build/carplay_tab5.bin`。不加 `--software-auth` 的构建显式设置 OFF，即使目录中存在材料也不会启用软件认证；无认证固件不能直接进入 CarPlay。

发布格式的本地构建命令仍为：

```sh
python scripts/release.py --auth local
```

产物位于 `artifacts/releases/v1.0.0/local-auth/`。`local-auth` 是现有构建变体名称，不表示其中身份仍然保密。已有设备升级只写应用区，保留配对、音量和亮度：

```sh
python -m esptool --chip esp32p4 -p <串口> write_flash 0x10000 build/carplay_tab5.bin
```

换手机时拔线 → 等待页 Clear pairing → 确认 → 重启 Tab5 → 接入已解锁手机并确认信任/允许 CarPlay。清理配对不会删除固件内的认证材料；认证身份与 NVS 手机信任记录是不同数据。

## 来源与公开范围

认证 provider 移植自 Carplay-S3 的 `src/vendor/auth_software_provider.c/h`，固定提交 `79a9f169f275b283f2909c5a326ed03c716c0d02`，保留 GPL-3.0-or-later。认证材料本身不按 GPL 重新许可。

根据本项目 2026-11-07 的获取与验证记录，材料来自 DiPlay v0.2.21 官方 Release APK 的 `assets/offline-mfi`。当时核对 APK SHA-256 为 `916c0708beb1022d4ea9678ff6a46dfb6d234f707837a2cbd80d615e8e2bb2e3`，未执行 APK；PKCS#7 容器内仅一张证书，提取 DER 后核对了证书与私钥匹配。本次提交沿用这三份文件，不包含 APK、手机配对记录或设备日志。

上游将材料追溯至公开 Carlinkit 固件；本项目只独立核对过 APK 及资源，没有独立证明更早来源或分发授权范围。来源记录：[Carplay-S3 认证材料来源](https://github.com/xmz28/Carplay-S3/blob/79a9f169f275b283f2909c5a326ed03c716c0d02/docs/认证材料来源.md)、[DiPlay v0.2.21 Release](https://github.com/shihabal3amri/DiPlay/releases/tag/v0.2.21)。

**私钥随当前仓库公开，且可从带认证固件中提取。不能将它视为保密或设备独有身份。** 公开提交是项目材料管理方式的变化，不代表获得 Apple/MFi 授权。其他私钥、个人身份、手机配对记录和实录日志仍应留在本地；Git 仅放行本目录列出的三份材料及说明、校验清单。

## 运行检查与实机证据

Lockdown 工作线程取得熵源后初始化 provider，检查证书扩展、公私钥匹配和原始 P-256 签名自检；签名调用使用互斥锁。只有手机实际返回 `0xAA05`，且证书、签名、ACK 顺序有效，才记录 `IAP2_AUTHENTICATED`。软件签名自检通过不等同于完整 CarPlay 连接成功。

2026-11-07 的首次验证仅完成当前手机接受身份，随后因 NCM 尚未配置停止；后续 v1.0.0 已完成实际视频、音乐、导航及设置短测，详见[发布说明](releases/v1.0.0.md)与[执行记录](执行记录.md)。这些结果不证明所有手机/iOS 兼容，也不等同于官方认证。

## 与 v1.0.0 首发快照的区别

已发布的 `v1.0.0` 标签、源码附件及 no-auth 开发固件保持首发内容，那个源码快照不含认证材料。材料是在首发后的当前 `main` 中补充；需要随项目取得材料时请使用当前 `main`，或按本页链接下载这三份文件放入旧版源码的同名目录。本次材料与文档提交不改写已有标签或固件附件。
