# Tab5 软件认证接入

2026-11-07。用户明确选择 Carplay-S3 文档描述的实验性软件认证路线。

## 来源

实现移植自 reference/Carplay-S3/src/vendor/auth_software_provider.c/h，固定提交 79a9f169f275b283f2909c5a326ed03c716c0d02，保留 GPL-3.0-or-later。认证材料本身不按 GPL 重新许可。

材料来自 DiPlay v0.2.21 官方 Release APK 的 assets/offline-mfi。下载 APK SHA-256 已核对为 916c0708beb1022d4ea9678ff6a46dfb6d234f707837a2cbd80d615e8e2bb2e3，与 Carplay-S3 来源记录一致。未执行 APK。PKCS#7 容器内只有一张证书，提取 DER 后已验证证书公钥与 PKCS#8 私钥匹配。文件位于忽略目录 secrets/mfi，权限仅本机用户可读写，不输出密钥内容。

上游说明将材料追溯至公开 Carlinkit 固件；本项目仅独立核对 APK 和其资源，没有独立证明更早来源或授权范围。

## 构建

在导出 ESP-IDF v5.5.3 后：

```sh
idf.py -DTAB5_PAIR_RESET_MAINTENANCE=OFF -DTAB5_SOFTWARE_AUTH=ON build
```

该选项默认 OFF，但 CMake 会保留上一次选择，后续不含实验身份的构建须显式传 -DTAB5_SOFTWARE_AUTH=OFF。开启时三份本地文件必须齐全。产物嵌入可提取的实验身份，不作为通用公开发行固件。

Lockdown 工作线程取得熵源后初始化 provider，检查证书扩展、公私钥匹配和原始 P-256 签名自检；签名调用使用互斥锁。只有手机实际返回 0xAA05，且证书、签名、ACK 顺序有效，才记录认证通过。

手机认证通过后仍可能停在 NCM 配置缺失；不能仅凭软件 signer 就宣称 CarPlay 投屏可用。现有 tab5_pair 记录保留，配对清理模式始终关闭。

## 本板实测结果

2026-11-07：原 Tab5 P4 v1.3 上签名自检通过，当前 iPhone 返回 0xAA05，IAP2_AUTHENTICATED；authenticated=1。后续 Identification 因 NCM 接口尚未配置而停止。日志位于 artifacts/device-2026-11-07/software-auth-runtime.log。此结果仅证明本轮当前手机接受该实验身份，不证明其他手机/iOS 或持续可用性。
